# 机器狗格斗 · MuJoCo 仿真训练成果说明

> 训练日期：2026-11-21 ｜ 版本 selfplay-03 ｜ 给队友看的简要说明

## 一、这是什么

在课程云端平台（AIStation 容器）里，用 **MuJoCo 4.0.1 物理引擎** 搭了一个**和真机 Lite3 机身一致的仿真机器狗**，训练它学会「把对手逼出圆形边界」的攻防能力，动作接口直接对齐真机。

**和之前「上帝视角 2D 点质点」版本的本质区别**：这次机体有真实质量、尺寸、惯性，感知也按真机传感器来模拟，不再是「训练时全知、上真机抓瞎」。

## 二、仿真里复刻了哪些真实

| 项 | 仿真值 | 来源 |
|---|---|---|
| 机身质量 | 11 kg（548×370 mm 箱体） | 运动开发手册 V2.0.1 |
| 腿连杆 | L1/L2/L3 = 102/200/210 mm | 同上 |
| 动作接口 | (vx, vy, wz) 速度级 | 真机 UDP `0x0140/0x0145/0x0141` |
| 速度上限 | [1.2, 1.0, 3.0] m/s · rad/s | `flat_rl_config.yaml` |
| 超声波 | `mj_ray` 射线测距，量程 4 m | 真机 USR-M10 |
| IMU | MuJoCo 原生陀螺仪/加速度 | 真机 IMU |
| 对手检测 | 方位角 + 距离 + 置信度（语义模拟） | 真机 YOLO 输出语义 |

**为什么对手检测用「语义模拟」而不是真的渲染图像跑 YOLO**：容器没有 GPU 渲染库，软渲染一帧要 25 ms 且和真机相机画面差距大。决策层真正用到的只有「对手在哪个方向、多远、可信度」，所以直接模拟这三样（带视场角 70° 裁剪、漏检 5%、距离噪声 0.08 m、方位噪声 0.03 rad），对齐的是「决策看到的信息」而不是「像素」。这些噪声参数是我先拍的，**周五连真机后要标定回填**。

## 三、比赛规则建模

- 场地：直径 5 米圆形边界
- 胜负：**无身体接触**（接触双方都判负）；一方出界判负
- 回合制：每回合只有一方进攻、另一方防守，下一回合互换
- 观测：10 维 `[自身速度×3, 超声波距离, 对手方位(sin/cos), 对手距离, 检测置信度, 距边界距离, 角色(+1攻/-1守)]`
- 动作：3 维 `(vx, vy, wz)`，归一化到 [-1,1] 后乘速度上限

## 四、怎么训练的

**自博弈（self-play）**：我方策略 vs 它的历史快照副本，每 2 万步刷新一次对手，让策略和自己「对打」进化。训练 20 万步，CPU 跑了 185 秒。

奖励设计（ego 视角）：
- 逼对手出界 +10，自己出界 −10，身体接触 −10
- 超时：防守方 +2（守住算小胜），进攻方 0
- 过程 shaping：进攻 = 逼近对手 + 逼对手往外 + 别自己跑出界；防守 = 留在场内 + 拉开与对手距离

## 五、结果

评估 20 回合，我方策略 vs 三种对手：

| 对手 | 胜 | 负 | 接触 | 超时 |
|---|---|---|---|---|
| 脚本逃跑者 runner | 20 | 0 | 0 | 0 |
| 脚本防守者 defender | 20 | 0 | 0 | 0 |
| 随机乱动对手 random | 0 | 0 | 0 | 20 |

**读法**：
- 对会逃跑/会防守的对手，我方**都能把它逼出界**（进攻学到了）；
- 对随机乱动的对手，我方逼不出去、但**也不输**（不接触、不出界、拖到超时）——因为「无接触」规则下，对手若死守圆心，任何狗都无解，这是规则决定的物理上限，不是策略 bug。

按角色分离评估也验证了行为是真实的：进攻角色会**逼近并往外推**（对手半径 1.2→2.5 m 出界），防守角色会**留在场内守住**（多数拖到超时）。
