# Lite3 全自主格斗 · 操作手册（2026-11-21 现场版）

> 一句话：**看见对手 → 转正 → 顶上去 → 丢了还顶一小会儿 → 摔倒就停 → 再爬起来找。**
> 全程不需要人碰摇杆，符合"全自主"要求。

---

## 0. 三十秒版本

```bash
# 电脑上（网线接狗的运动主机）
python deploy_fight.py --probe          # 上传 + 体检（不动狗）
# 狗上
ssh ysc@192.168.1.120                   # 密码是单引号 '
cd ~/fight && bash run_fight.sh dry     # 干跑 25 s，狗不动，只看流程
cd ~/fight && bash run_fight.sh fight   # 真打
bash run_fight.sh stop                  # 随时停
```

**第一次一定先 `dry`。** 不加 `--apply`，程序一个运动字节都不会发给狗。

## 1. 五条安全铁律（别跳）

1. **狗趴地或架起再试程序**，第一次永远用 `dry`；第一次 `fight` 用 `gentle` 预设、`--stand` 不加。
2. 停程序用 `bash run_fight.sh stop`（发 SIGTERM，程序会先零速再复位）。**不要 `kill -9`** —— 虽然心跳断了 1 s 狗也会自己停，但那 1 s 里它还在按最后的速度跑。
3. 顶的时候人站**侧面**，不要站在两台狗的正前方或正后方。
4. `~/module/deploy.sh` 会 `dd` 写 boot 分区，**永远不要执行**；备份包里有 `.ssh` 私钥，不要外传。
5. 第一次真打，先问裁判三件事：**怎么算赢？出界算输吗？狗摔倒了可以扶吗？**（第二条决定要不要开自动爬起）

## 2. 它在怎么打（状态机）

```
        ┌──────────── 没看见目标 ────────────┐
        ↓                                    │
     [SEEK] ──看见──> [AIM] ──接触──> [PUSH] ─┘
     原地左右转        转向+靠近       定速硬顶
        ↑                │              丢了目标:
        │                └────丢>0.6s────┘ 继续顶 ≤1.5 s（盲推）
        │
   [RECOVER] <── 检测到摔倒（可选，默认关）
    停 1 s，等它自己稳住（不自动起立 —— 起立指令是 toggle，发错 = 主动趴下）
```

| 状态 | 发什么 | 换出条件 |
|---|---|---|
| IDLE | 0, 0 | 开打触发 |
| SEEK | vx=0, wz=±0.7 rad/s（每 1.2 s 换向） | 看见目标 |
| AIM | vx=0.55×门控, wz=1.8×偏差角 | 面积达 `contact_area` 且角度 <0.35 |
| PUSH | vx=0.75, wz 小修正 | 顶满 2.5 s / 丢目标 1.5 s |
| RECOVER | 0, 0 | 1 s 后回 SEEK |

**三个预设**（`--preset`）：

| 预设 | 靠近 m/s | 顶 m/s | 判接触面积 | 适合 |
|---|---|---|---|---|
| `gentle` | 0.30 | 0.40 | 13% | **第一次上场**，先确认"它会不会顶" |
| `push` | 0.55 | 0.75 | 11% | 默认，稳 |
| `ram` | 0.85 | 1.00 | 9% | 场地大 / 对手跑得快 |

### 为什么这么设计（讲给老师听）
- **不追精度，追鲁棒**：单目 + 无雷达，距离靠"目标框面积"这种粗糙信号，粗就粗，但 6 帧内就能判出"近/远"。
- **不用 YOLO**：狗上唯一现成模型是 RKNN 的 `yolov5s-640-640.rknn`，要配 Python 版 rknn 运行时 + 绑核，跑一次约 50 ms；MOG2 运动块在 320 宽上只要 5~10 ms，而且**对手一定是动的**，正好是它的强项。
- **速度走 0x0140 双精度通道**（真实 m/s、无死区），不走摇杆轴通道（±6553 死区 = 20% 行程，轻推根本发不出去）。
- **失控就停**：相机卡 0.5 s、超时长、Ctrl-C、任何异常 → 先零速，再关连续步态、回手柄模式。

## 5. 现场五步（照顺序做，30 分钟内能打完）

### 第 1 步：连上 + 体检（3 分钟，狗趴着）
```bash
cd ~/fight && bash run_fight.sh check
```
必须看到：`python3` 有版本、**`cv2 : 4.x.x` 是绿的**、`jy_exe : 在跑`、`43893 : 在监听`、`摄像头 : /dev/video0`。
> 如果 `cv2` 红了 → 跳到第 9 节 B 计划，别浪费时间。

```bash
python3 fight.py probe
```
这一步会告诉你：**相机实际分辨率/帧率**、**帧龄（采集到到手多少 ms）**、遥测有没有、以及 `flat_rl_config.yaml` 里**现场真正生效的 `max_velocity_target`**。
> 帧龄 >150 ms 就别用快速冲撞，改 `gentle`。

### 第 2 步：调感知（5 分钟，狗架起或趴着，镜头前晃一台狗/一块纸板）
```bash
bash run_fight.sh calib 60
```
看输出：`found bearing=+0.35 area=0.0800`。
- 把对手的狗放在**1 m 正前方**，记下 `area` —— 这就是"接触面积"的参考值。
- 如果平时 `none` 但狗在动 → `--min-area` 调小（默认 200）；如果到处误检 → `--var-thresh` 调大（默认 24）。
- **重要**：如果画面下方能拍到自己机头（会一直抖），加 `--roi-bottom 0.85` 把它裁掉。

### 第 3 步：干跑（3 分钟，狗趴着不动）
```bash
bash run_fight.sh dry
bash run_fight.sh log
```
看日志里状态有没有按 `IDLE→SEEK→AIM→PUSH` 走，有没有 `!!` 警告。这一步一个运动字节都不发。

### 第 4 步：手动确认"能顶"（10 分钟，人用原厂手柄/App）
**这一步不是跑我们的程序**，是你用原厂手柄把狗开上去顶两下，确认：
- 狗顶得住、不打滑；
- 对手的狗被顶得动；
- 场地边界在哪、出界算不算输。
> 这几分钟比任何代码都值钱 —— 它决定第 5 步用 `gentle` 还是 `ram`。

### 第 5 步：真打（狗站好、周围清空、人站侧面）
```bash
# 先来一次温和的
PRESET=gentle bash run_fight.sh fight
# 顺利的话
PRESET=push DUR=180 bash run_fight.sh fight
# 想留证据（录像 + 逐帧图 + CSV，约 30 MB）
VIDEO=1 CSV=1 PRESET=push bash run_fight.sh fight
```
开打后：`armed` 后 5 s 或"看见目标"就自动开打，不用碰键盘。
`bash run_fight.sh stop` 随时停。

## 6. 参数速查（现场只动这几个）

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `--preset` | push | 第一次 `gentle`，正式 `push`，拼速度 `ram` |
| `--max-v` | 预设 | 靠近太快刹不住 → 调小 |
| `--push-v` | 预设 | 顶不动 → 调大；顶飞/打滑 → 调小 |
| `--contact-area` | 预设 | **必调**：第 2 步量到的 1 m 面积 × 0.8 左右 |
| `--kp-yaw` | 预设 | 转向画龙 → 调小；转不过来 → 调大 |
| `--max-wz` | 1.2 | 一直原地打转 → 调小 |
| `--lost-grace` | 0.6 | 一丢就发呆 → 调大 |
| `--blind-time` | 1.5 | 盲推太猛冲出去 → 调小 |
| `--duration` | 180 | 按比赛时长 -20 s |
| `--delay` | 5 | 裁判喊开始到狗动的时间 |
| `--chan` | vel | 速度通道不动 → 改 `axis`（会自动切手柄模式） |
| `--gait` | medium | 顶不动想更猛 → `fast`（但更难控） |
| `--stand` | 关 | **狗是趴着的时候**加一次（toggle，只发一次） |

所有参数：`python3 fight.py run --help`

## 7. 规则变了怎么办

| 如果规则是… | 改什么 |
|---|---|
| **把对方推出圈**（相扑式） | 用 `push`，`--push-time 3.0`（顶久一点别松） |
| **把对方顶倒** | 用 `ram` 冲撞；再加 `--contact-area 0.07`（更早开始顶） |
| **抢中间的旗/球** | 先别用这套：得改成"看目标物"（把 `--min-area` 调小、`--contact-area` 改成目标物面积） |
| **限时比谁把对方推得更多** | `push` + `--blind-time 2.0`（丢了也继续顶） |
| **有"受伤/碰撞"限制** | 用 `gentle`，`--push-v 0.35` |

## 8. 故障排查

| 症状 | 原因 | 处置 |
|---|---|---|
| 狗完全不动 | 没加 `--apply` / jy_exe 没跑 / 模式没切 | 看日志有没有"已 armed"；`bash run_fight.sh check` |
| 狗原地踏步不前进 | 上一轮进程还在发零速帧 | `bash run_fight.sh stop` 后再开（脚本已带自动清场） |
| 一直原地转圈 | 没检到目标，在做 SEEK 扫描 | 正常。`calib` 看能不能检到；不行就调 `--min-area` |
| 对着空气顶 | 误检（自己的腿/影子） | `--roi-bottom 0.85` + `--var-thresh 32` |
| 看到对手但不动 | 角度大，门控把 vx 压到 0.12 了 | 正常。想更激进加 `--aim-gate 1.5` |
| 抖/画龙 | `kp_yaw` 太大或 `bearing-lpf` 太小 | `--kp-yaw 1.2 --bearing-lpf 0.85` |
| 相机打不开 | 被别的程序占了（比如 `track`） | `pgrep -af track`，`pkill -f track` |
| 帧龄 >300 ms | USB 带宽/曝光太高 | 降 `--width 640 --height 480`，坚持用 MJPG |
| 日志一堆 `!!` | 看具体哪条，都有中文原因 | — |

**B1. 狗上没有 cv2** → `pip3 install opencv-python-headless`（要能上网）。
上不了网就换 **B2**：
**B2. 把大脑放到感知主机 103 上跑**（它有 ROS + OpenCV，且 `network.toml` 的遥测目标就是它）：
```bash

    --state-port 43897 --delay 8
```
代价：RTSP 多 100~200 ms 延迟。好处：遥测能收到，摔倒检测可用。
**B3. 速度通道不走** → `--chan axis --axis-vmax <yaml 里的 max_velocity_target[0]>`（脚本会自动切手柄模式）。
**B4. 单目实在不行** → 超声波（`/us_publisher/ultrasound_distance`）只在 ROS 里，120 无 ROS，别指望；退化成"固定航向盲推 + 时间窗"。

## 10. 赛后复盘（这是加分项）

比赛时开 `VIDEO=1`，会得到 `~/fight/logs/` 下三样东西：

- `fight_TS.log` —— 状态迁移全过程（哪一秒进 PUSH、为什么退出）
- `fight_TS.csv` —— 每 0.1 s 一行：`t, state, found, bearing, area, vx, wz`
- `frames_TS/*.jpg` —— 标注帧（框 + 方位 + 速度）

**怎么用**：把 CSV 拉进 Excel，画 `bearing` 和 `area` 的时间曲线。
如果 `area` 一直上不去但状态已经是 PUSH → 说明 `contact-area` 判早了；如果 `bearing` 来回振荡 → `kp_yaw` 大。
这套东西写进报告里，比"我们赢了"有说服力得多。

## 11. 已知风险（诚实版）

1. **摔倒检测没有实机验证**：`0x0901` 状态帧里 roll/pitch 的偏移我没有文档，只解析了 `basic/gait/yaw`。所以默认 `--fall-imu` 关闭 —— 狗倒了它就停在那里，别指望它自己爬起来（自动起立是 toggle，发错就变成主动趴下，风险更大）。
2. **接触判据是"框面积"**：对手横着站和正面站，同样距离下框面积差一倍。所以 `--contact-area` 必须现场用第 2 步量一次。
3. **单目没有真实距离**：`--obj-w/--hfov` 那套几何测距没启用，因为焦距未知。想用就先量：1 m 处框宽 = W 像素 → `fx = W × 100 / 40`（假设狗身宽 0.4 m）。
4. **多狗同场，WiFi 干扰**：所以坚持有线 + loopback，别用无线。
5. **顶的位置**：程序只会"正对着顶"，不会侧顶/绕后。要侧顶得再加一个"横向偏移"状态，比赛前 10 分钟改不现实。
